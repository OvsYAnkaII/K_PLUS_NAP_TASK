# Задание от НАП - подсчет пар слов в файле на определенном расстоянии

[![C++](https://img.shields.io/badge/C++-11-blue.svg)](https://isocpp.org/)
[![CMake](https://img.shields.io/badge/CMake-3.10+-green.svg)](https://cmake.org/)

Утилита для анализа текстовых файлов и подсчета пар слов в пределах заданного расстояния. Поддерживает multilingual текст, игнорирует пунктуацию и использует эффективный алгоритм скользящего окна.

### Кратко
- Вход: путь к файлу, два целевых слова, максимальное расстояние между словами (целое число ≥ 0).
- Выход: одно число — количество пар вхождений `word1` перед `word2`, у которых количество слов между ними ≤ заданного расстояния.
- Обработка текста: игнорирует пунктуацию по краям токенов, поддерживает Unicode (в т.ч. кириллицу).


## Структура репозитория
- `cpp_executer/`
  - `main.cpp` — CLI-обертка над алгоритмом, парсинг аргументов, вывод результата/ошибок.
  - `file_pair_words_search_distance.h` — реализация алгоритма:
    - `cleanWord` — очистка слова от неалфавитных символов по краям;
    - `countWordPairsAtMaxDistance` — скользящее окно и подсчет пар.
  - `test.h` — генерация тестовых файлов и демонстрационные вызовы (не используется в CLI).
  - `CMakeLists.txt` — сборка исполняемого файла `cpp_executer` (C++20).
- `python_tests/`
  - `features/word_pairs.feature` — сценарии behave (успех/ошибки/краевые случаи).
  - `features/steps/word_pairs_steps.py` — запуск собранного бинарника и проверки.
  - `test_files/`, `target_files/` — входные данные для тестов.


## Установка и сборка
Требования:
- CMake (рекомендуется 3.10+), компилятор с поддержкой C++20.

Сборка:
```bash
cd cpp_executer
mkdir -p build && cd build
cmake ..
make
```
В результате появится исполняемый файл `cpp_executer` (путь: `cpp_executer/build/cpp_executer`).


## Запуск
Сигнатура:
```bash
./cpp_executer <file_path> <word1> <word2> <max_distance>
```
Параметры:
- `file_path` — путь к текстовому файлу;
- `word1` — первое слово (левое);
- `word2` — второе слово (правое);
- `max_distance` — максимальное количество слов между `word1` и `word2` (целое число ≥ 0).

Коды завершения и сообщения:
- Успех: код 0, в stdout печатается одно число — результат.
- Ошибки (код ≠ 0):
  - неправильное число аргументов;
  - `max_distance` не число;
  - `max_distance < 0`;
  - не удалось открыть файл.

Примеры:
```bash
# пары "apple" перед "banana" с расстоянием ≤ 0 (соседние слова)
./cpp_executer path/to/file.txt apple banana 0

# пары "налоги" перед "России" с расстоянием ≤ 5
./cpp_executer path/to/russian.txt налоги России 5
```


## Как работает алгоритм
В `countWordPairsAtMaxDistance` используется очередь (скользящее окно) и счетчики целевых слов:
- Очистка токена функцией `cleanWord` убирает ведущие/замыкающие неалфавитные символы, оставляя буквы, цифры и не-ASCII (для Unicode).
- При чтении каждого слова:
  - добавляется в окно;
  - если это `word1`, увеличивается счетчик `word1` в окне;
  - если это `word2`, к результату добавляется текущее количество `word1` в окне;
  - если размер окна становится больше `max_distance + 1`, выталкивается самый старый токен и при необходимости уменьшается счетчик `word1`.

Сложность:
- Время: O(N), где N — количество слов (одно прохождение).
- Память: O(K), где K ≈ `max_distance + 1` (размер окна).

Замечания:
- Подсчитываются только пары, где `word1` встречается перед `word2`.
- Слова сравниваются по точному совпадению с учетом регистра (при необходимости нормализацию можно добавить).


## BDD-тесты (behave)
Требования:
- Python 3.9+ и `behave`. В каталоге `python_tests/venv` присутствует локальное окружение; при желании можете использовать системное.

Подготовка окружения (вариант без встроенного venv):
```bash
cd python_tests
python3 -m venv .venv
source .venv/bin/activate
pip install behave
```

Сборка бинаря перед тестами:
```bash
cd cpp_executer && mkdir -p build && cd build
cmake .. && make
```

Запуск тестов:
```bash
cd python_tests
behave
```
Шаги тестов ожидают, что бинарь находится по пути, аналогичному:
```
cpp_executer/build/cpp_executer
```
Если вы собираете в другую директорию, поправьте путь в `python_tests/features/steps/word_pairs_steps.py` (переменная `CPP_PROGRAM`). Сейчас он вычисляется относительно корня проекта.


## Примеры сценариев
- Корректные входные данные — успешное завершение и точный результат.
- Отсутствующий файл — завершение с ошибкой.
- Отрицательное или нечисловое `max_distance` — завершение с ошибкой.
- Ввод картинки вместо текста — успешное завершение с результатом (файл представляется в виде байт, что несильно отличается от .txt).


## Ограничения и допущения
- Сравнение слов — точное, регистрозависимое.
- Очистка токена удаляет неалфавитные символы только по краям. Внутренние дефисы/апострофы сохраняются.
- Поддержка Unicode базовая (опирается на байтовую проверку символов как «не-ASCII»).
